# Agent Loop Lab

这是 Agent 工程师基线评估后的第一份教学实验。它不调用真实模型，也不使用 Agent 框架，而是用一个可预测的脚本模型把 Agent 的核心运行机制暴露出来。

## 学习目标

运行并理解这条链路：

```text
任务 -> 宿主循环 -> 模型决定 -> 工具校验与执行 -> 新观察
                    ^                              |
                    |______________________________|

满足停止条件 -> 结构化最终输出
```

重点不是脚本模型有多聪明，而是看清哪些职责属于模型，哪些职责必须由确定性宿主代码控制。

## 运行

```bash
cd tools/agent-loop-lab
npm run demo
npm test
```

项目没有第三方依赖，不需要安装包或配置 API Key。

## 文件职责

- `src/agent.mjs`：宿主循环，控制步数、工具执行、重复失败和最终输出校验。
- `src/scripted-model.mjs`：可预测的模型适配器，负责根据当前观察决定下一步。
- `src/tools.mjs`：两个只读工具及其参数校验。
- `src/schema.mjs`：最终分诊结果的确定性校验。
- `src/data.mjs`：实验使用的项目与事件数据。
- `test/agent.test.mjs`：成功和失败路径的固定测试。

## 第一课

1. 运行 `npm run demo`，从 trace 中找出每次“模型决定”和“工具观察”。
2. 阅读 `src/agent.mjs`，回答：为什么 `maxSteps`、工具参数校验和输出 Schema 不能只写在 Prompt 里？
3. 阅读重复失败检测，回答：为什么同一错误第二次出现时直接停止，而不是继续让模型重试？
4. 阅读测试，指出哪一个测试验证的是安全边界，哪一个验证的是预算边界。

## 下一项修改

理解现有实现后，再新增第三个只读工具 `get_project_risks(projectId)`。新增时必须同时提供参数校验、返回契约和测试。不要先接入真实模型。

## 过关标准

- 能用自己的语言解释一次完整循环。
- 能指出模型职责与宿主职责的分界。
- 能独立新增一个工具而不破坏现有测试。
- 能解释五类失败：非法输入、未知工具、重复失败、无效最终输出和超出步数预算。
